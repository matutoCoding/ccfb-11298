# 结毯工坊 · 打结地毯剪花绒面工艺系统

上机前在浏览器里把**结图、剪花、绒面**全部定死的工艺系统。TypeScript + WebGL2，渲染着色器全部手写，无第三方 3D 引擎。

## 启动

```bash
npm install
npm run dev        # 开发，默认 http://127.0.0.1:5180
npm run build      # 生产构建到 dist/
npm test           # 物理一致性 + 着色器静态检查
npm run typecheck  # 仅类型检查
```

## 五个页面与工艺链路

| 页面 | 干什么 |
|---|---|
| 订单列表 | 建订单（成品尺寸 mm、道数=每英尺结数），数据存 IndexedDB，刷新不丢 |
| 结图转换 | 导入设计稿 → 按道数换算成结网格 → 纱线色卡 Lab 量化吸附 → 锯齿/细线风险标红 → 相近色手动合并 → 中心大花/边框/角花区域分解与四角对齐 |
| 剪花工艺 | 基准绒高、片剪斜沟（沟深/沟宽/斜度）、按色号的高低绒浮雕；生成逐结高度场，热力图 + 侧面剖面实测沟深 |
| 绒面预览 | 壳层+边缘鳍片+逐纤维片元渲染；羊毛/丝/羊毛夹丝三种光泽；染缸横向色差条带；平铺/挂墙/翻看背面；侧光看沟槽阴影；截图带订单参数 |
| 设置 | 色卡增删改、纱线线密度、折叠倍数、壳层数；每色号结数与克重清单，导出 CSV |

## 三条硬约束如何保证

1. **沟深设多少、剖面量出来就是多少**
   高度场单位即物理 mm。片剪用两遍 chamfer 距离场求每结到花型轮廓的物理距离，V 形剖面直接按设定 `depth` 减绒高，沟底保底 0.5mm 不剪穿。`scripts/test-physics.ts` 对 1.5/2.5/4.0mm 三组沟深做数值断言，实测落差与设定误差为 0。剪花页右侧剖面图标注实测值，下方校验条给出"物理一致 ✓"。

2. **换道数后克重按结数重算**
   道数变化 → `gridFromSpec` 重算 cols/rows 与结间距 → 结图重采样、高度场重建 → 克重清单用 `每结长度 = 绒高×折叠倍数×2臂 + 结头余量`、`克重 = 长度×线密度` 逐结累加。测试覆盖 80→120 道结数与克重同步增长。

3. **贴近看是一根根绒尖、转动不闪、60fps**
   - 所有随机量（绒丝位置、倾斜、夹丝闪烁单元）都从**物体空间整数结坐标 + 固定种子**哈希得到，不含时间/屏幕坐标，视角旋转时同一结永远是同一根绒丝，不闪烁。
   - 壳层体积 + 片元内逐结 3~5 根纤维 + 顶端收尖，避免"一层层薄片"；毯外缘用实例化鳍片补绒头侧影。
   - 渲染网格分辨率封顶（长边 260 段），结级颜色/绒高走全分辨率纹理在片元采样，三角形数量与结数解耦；实测 RTX 3060 上单帧 GPU 成本 < 1ms。

## 物理单位约定

- 全系统长度统一 **毫米 mm**；道数 kpi = 每英尺结数，结间距 = 25.4 / kpi。
- 高度纹理 R16F（半精度浮点，毫米），结索引纹理 R16UI（最多 65535 色号），色卡纹理 RGBA8（sRGB 颜色 + 材质编号）。
- 光照在着色器内线性空间计算，输出前一次性转回 sRGB。

## 已知边界

- 浏览器需支持 WebGL2 与 EXT_color_buffer_float（近五年主流浏览器均可）。
- 单毯结索引纹理上限 65535 色号；实际色卡通常数十个，无瓶颈。
- Playwright 等受控无头浏览器会把 requestAnimationFrame 节流到 ~1fps，这是测试环境行为；真实桌面浏览器以 GPU 实测帧时为准（< 1ms/帧）。
